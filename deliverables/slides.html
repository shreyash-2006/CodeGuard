CodeGuard

Real-time, pre-execution safety for LLM-generated code.

  • CPU-only · no LLM calls anywhere · fail-closed
  • One call: POST /check {"code": "..."} → verdict before it runs
  • Dashboard /ui/ · API codeguard-bdmu.onrender.com/check

02The problem

  • AI agents now write and execute code autonomously
  • Existing scanners are batch / CI tools — too slow to sit inline
  • The task: a fast, local checkpoint for every snippet
  • No LLM-as-judge · CPU-only · fixed schema · a live endpoint

The gap isn't detection quality — it's timing.

03What CodeGuard is

POST /check  {"code": "..."}

{
  "verdict":         "block" | "allow",
  "risk_score":      0.0 – 1.0,
  "categories":      [ 9 fixed strings ],
  "code_language":   "python" | "bash" | "javascript" | "sql" | "yaml" | "markdown" | "unknown",
  "reason":          "human-readable, secrets masked",
  "vulnerable_lines":[ 1-based ints ]
}
  • block ⟺ categories non-empty ⟺ risk_score ≥ 0.5 — one invariant, one function
  • Never 4xx/5xx on /check; malformed input → valid allow

05Architecture

preprocess → langid → segment → deobfuscate → parse
          → detectors (+ benign dampers)
          → ML (calibrated backup) → fusion → explain → finalize_response()
          → JSON
  • Rules encode attack stories: sensitive source → processing → network sink (MITRE-tagged)
  • Benign dampers suppress lookalikes (parameterized SQL, ast.literal_eval, docstrings, allowlisted hosts)
  • Layered deobfuscation — base64/hex/chr/concat/alias/rot13/shell, with line maps
  • ML is a calibrated backup, not the judge

06The nine categories

secret_accessdata_exfiltration destructive_commandobfuscated_execution persistence_or_privescresource_exhaustion ssrf_network_exfilai_targeted_instructions dependency_risk
  • Across Python, Bash, JavaScript, SQL, YAML, Markdown
  • Includes AI-targeted prompt injection in comments, strings, docstrings and CI workflows

07Guarantees — why it's deployable

  • Schema invariant enforced in one function — /check always HTTP 200
  • Fail-closed: any error or timeout → a valid block
  • Never hangs: 2 s hard timeout + bounded regexes + input/line caps
  • Deterministic; model loaded once at startup; missing model → rules-only

For a judged endpoint, availability is a feature.

09Key design decisions

  • Dampers > detectors for the score — all benign lookalikes explicitly suppressed
  • Multi-label, top-k categories (dev labels are fuzzy & co-firing)
  • Rules carry the verdict (ablation); ML is a calibrated backup
  • No hard-coded answers — rules encode stories; model trains on generated templates
  • Interception proven with an observable side effect (marker file)

10Limitations & roadmap

  • Heuristic language ID; taint is intra-snippet; deobfuscation is bounded
  • Two per-category F1s dip on the stress set due to label co-firing (verdict unaffected)
  • Next: inter-procedural taint · ONNX cascade · grow the template bank from new evasions
